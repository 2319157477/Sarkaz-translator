# Sarkaz Decoder 设计文档

## 问题描述

将中文字符的 Unicode 编码模 56，余数通过查表映射到英文字母。需要将编码后的英文字符串还原为原始中文语句。

核心难点：mod 56 不可逆，每个字母对应 750-1100 个候选汉字，搜索空间巨大。

## 约束条件

- 输入：任意中文句子（汉字 + 标点 + 数字）
- 运行环境：允许调用 LLM API
- 输出：top-N 候选句列表，用户自行选择
- LLM 仅用于打分，不生成新候选

## 方案：N-gram 粗筛 + LLM 精排

### 第一层：数据层——反向索引与频率表

1. **反向索引** `letter → List[char]`
   - 从映射表反转：letter → 余数列表
   - 对每个余数 r，扫描目标字符范围，找出所有 `unicode(c) % 56 == r` 的字符
   - 字符范围：CJK 基本区 U+4E00~U+9FFF、中文标点 U+3000~U+303F / U+FF00~U+FFEF、ASCII 数字 0-9
   - 每个字母最终对应约 750-1100 个候选字符

2. **字符频率表**
   - 使用公开的中文字符频率数据（覆盖常用 ~7000 字）
   - 对反向索引中的候选按频率降序排列
   - 预过滤：每个位置只保留频率 top-K（默认 50）的候选

3. **字符 Bigram 频率表**
   - 字符级二元组频率
   - 用于 beam search 的转移打分
   - 从公开中文语料统计或使用现有 NLP 资源

### 第二层：粗筛层——Beam Search 解码

1. **解码流程**
   - 对输入字符串的每个字母，查反向索引得到候选字符集（top-K）
   - 从左到右逐位展开，维护 beam_width 条路径（默认 200）
   - 打分 = 累积分 + log(bigram_prob(prev, cur)) + λ × log(unigram_freq(cur))
   - λ 为 unigram 权重系数，默认 0.3

2. **剪枝策略**
   - 每步只保留 top beam_width 条路径
   - 标点和数字候选集天然很小，自动收敛
   - 句首/句尾加 BOS/EOS token，利用句首字频分布加权

3. **输出**
   - 产出 top-50 条完整候选句，附带累积对数概率得分

### 第三层：精排层——LLM 打分 + 验证

1. **LLM 打分**
   - 将 top-50 候选句批量发给 LLM API（单次请求）
   - LLM 对每条候选句的自然度/通顺度打分（1-10），按得分降序排列
   - LLM 不生成任何新内容，只做评判

2. **验证环节**
   - 对排序后的候选，重新编码验证（char → unicode % 56 → 查表 → letter）
   - 与原始输入逐字符比对，不匹配的丢弃
   - 防御性校验，理论上 beam search 产出的候选都应通过

3. **输出**
   - 返回 top-N 条验证通过的候选句（默认 N=5）
   - 每条附带：LLM 自然度得分、beam search 统计得分

4. **API 成本**
   - 单次解码只需 1 次 API 调用
   - 输入约 2000 tokens，输出约 500 tokens

## 模块划分

| 模块 | 职责 |
|------|------|
| `mapping.py` | 映射表定义 + 反向索引构建 |
| `frequency.py` | 字符频率表 / bigram 频率表加载 |
| `beam_search.py` | beam search 解码器 |
| `llm_scorer.py` | LLM API 打分封装 |
| `decoder.py` | 主流程编排 |
| `encoder.py` | 编码器（用于验证） |

## 主流程

```
encoded_string → decoder.decode(s, top_n=5)
  ├─ mapping.reverse_lookup(letter) → 候选集
  ├─ beam_search.search(candidates, beam_width=200) → top 50 句
  ├─ encoder.verify(candidates, original) → 过滤非法
  ├─ llm_scorer.score(candidates) → 打分排序
  └─ return top_n results
```

## 配置项

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `beam_width` | 200 | beam 宽度 |
| `candidate_k` | 50 | 每位置候选数 |
| `top_n` | 5 | 最终返回条数 |
| `llm_model` | 可配置 | LLM API 模型 |
| `lambda_unigram` | 0.3 | unigram 权重系数 |

## 数据依赖

- 字符频率表：公开数据集，项目内以 JSON 存储
- Bigram 频率表：预处理后以 JSON 或 pickle 存储
- 映射表：硬编码在 `mapping.py` 中

## 测试策略

- 正向验证：随机取中文句子 → 编码 → 解码 → 检查原句是否在 top-N 中
- 边界测试：纯标点、纯数字、单字、长句（50+ 字）
- Beam search 单元测试：小规模候选集验证路径选择正确性
- LLM 打分测试：mock API 验证排序逻辑

## 性能预期

- Beam search：单句（10-20 字）< 100ms（纯 Python）
- LLM 打分：取决于 API 延迟，通常 1-3 秒
- 内存：反向索引 + bigram 表约 50-100MB
