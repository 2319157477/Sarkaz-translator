## Project Overview

Sarkaz Decoder: reverses a mod-56 encoding that maps Chinese characters to English letters (from the game Arknights). Each letter maps back to 750-1100 candidate characters, so the decoder uses n-gram beam search + LLM reranking to reconstruct the most likely original Chinese sentence.

## Commands

```bash
# Run decoder
python main.py <encoded_string>
python main.py -i                    # interactive REPL

# Run tests
python -m pytest tests/ -v
python -m pytest tests/test_mapping.py -v   # single test file

# Rebuild frequency data from game corpus
python scripts/build_ngram_stats.py
```

## Architecture

Three-layer pipeline: **Data -> Beam Search -> LLM Reranking**

- `src/mapping.py` — hardcoded FORWARD_MAP (56 remainder-to-letter entries). `build_reverse_index()` scans CJK/punctuation/digit Unicode ranges, groups characters by `codepoint % 56` into `letter -> [chars]`.
- `src/frequency.py` — loads JSON frequency tables (unigram, bigram, trigram, fourgram, transition matrix). Sorts candidates by frequency or transition probability.
- `src/beam_search.py` — left-to-right beam search over candidate characters. Scoring: `log(bigram) + λ_uni * log(unigram)` with optional trigram/fourgram bonuses. Uses precomputed log-probability transition matrix.
- `src/llm_scorer.py` — sends top-50 beam results to an OpenAI-compatible API, asks for naturalness scores 1-10, re-sorts by score.
- `src/decoder.py` — orchestrates the pipeline: prepare candidates (punctuation always included, non-punctuation top-K by unigram) -> beam search -> verify by re-encoding -> LLM score -> return top-N.
- `src/encoder.py` — encodes Chinese -> English (used for roundtrip verification).
- `src/config.py` — all tunable parameters (beam width, candidate K, lambda weights, LLM credentials).

## Data Files

All in `data/`. Generated by `scripts/build_ngram_stats.py` from `data/cn_texts.json` (game text corpus). The transition matrix (`game_transition.json`, 1.7MB) is the largest file.

## Key Design Decisions

- mod-56 is not invertible; collisions are handled by maintaining all candidates and scoring statistically
- LLM is used only for reranking, never for generating candidates
- Punctuation candidates bypass frequency filtering (always included at every position)
- Re-encoding verification ensures output is consistent with input
